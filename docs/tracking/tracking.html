Strategy call tracking plan

What to send, when, and the JSON for each event. All events go to Segment. Every name starts with meeting_.

Include on every event

  1. Every event includes the UTMs, as separate properties. Send each UTM as its own property, never nested, never hardcoded values. We need all the UTM parameters we use now for tracking ads, plus two new ones: utm_location and utm_team. No ad click ids.
    first_touch_* is the first marketing touch ever.
    last_touch_* is read from the latest visit that carried tracking parameters. Any visit with a parameter replaces it; a visit without leaves it as it was. The page where the CTA was clicked is source_page.
  2. Segment call type. The three page-view events are Segment page() calls (type page, category meeting, name = the event name). Send one page call per page load with that name, and do not also send a second generic page() on those pages. Everything else is a track call.
  3. Who and what: hutk (the HubSpot cookie), email and hashed_email as soon as the email is known, booking_id once the booking exists, and the flow properties: booking_session_id, anonymous_id, flow_entry, flow_start, source_page, cta_id, variant_booking, variant_confirmation.

Where to send

  • Segment workspace databox, source leads. Keys page
  • Browser events: Analytics.js with the source write key. Server events: the Segment HTTP Tracking API with the same write key.
  • This source is only for contacts without a Databox account. Once someone has an account, their events go to the production source.

Properties on every event

Besides the UTMs (rule 1), every event carries these.

PropertyTypeWhat it holds
anonymous_idstringSegment anonymous id. Joins every event before the person is known. Passed as ajs_aid across domains.
hutkstring or nullThe HubSpot tracking cookie (hubspotutk). Ties the visitor's HubSpot activity, such as the ad click, to the contact. Null if the HubSpot script did not run or cookies were declined. Also sent in the Cal.com booking metadata. Added.
booking_session_idstringCreated at the CTA click, or at the first flow page if there was no click. The one id the scheduler must return.
flow_entryenumWhat delivered the visitor to the flow: cta, ad, email, direct.
flow_startenumWhich page they entered the flow on: booking_page or calendar.
source_pagestring or nullPath of the page where the CTA was clicked. Null on targeted ads, marketing emails and direct visits. Never the booking page itself.
cta_idstring or nullThe data-cta id of the clicked CTA. For marketing emails: email id plus link id.
variant_bookingenum A or BBooking page A/B variant. Sticky per visitor, stored on the booking.
variant_confirmationenum A or BConfirmation page A/B variant. Sticky per visitor.
emailstringThe visitor's email, on every event from the moment it is known (form submit, or the calendar details). Anonymous before that: join those earlier events to the later ones on anonymous_id or booking_session_id (hutk also works in HubSpot). Added.
hashed_emailstringThe hashed email. On every event from the moment the email is known. Replaces the ad click ids for matching conversions to ads. Added.
booking_idstringThe Cal.com booking id, on every event once the booking exists. Added.

HubSpot: creating the contact

Do not rely on the event to create the contact. HubSpot may not create one from an event, and an event that arrives before its contact can be lost. The contact is created or updated first, with everything we know, and the event is sent after it.

  • Recommended: our server (the one that fires meeting_form_submitted and meeting_booking_confirmed) upserts the contact with the HubSpot API, matched on email, and only then sends the Segment event. This keeps the order and lets us set the owner. It needs a HubSpot private app token on the server, with contact write access (and lead write access, if a Lead is created).
  • Alternative: the Segment HubSpot destination has an upsert-contact action, mapped from meeting_form_submitted and meeting_booking_confirmed. No server code, but Segment does not guarantee that the contact exists before the event reaches HubSpot, and it cannot set the owner.
  • When no form ran (targeted ad straight to the calendar), the contact is created from meeting_booking_confirmed instead.
  • In the browser, call _hsq.push(['identify', { email }]) once the email is known, so HubSpot links its tracking cookie (hutk), and with it the ad click, to the contact.
